# Queued editor-basis worker experiment — correctness slice

written with gpt-6 in codex

Separate arm of the serial worker session proof. No production routing. Latest source passed types/build and 46 real-browser assertions. Prior 35-assertion bundle provenance remains separate. Begin forks the actual session Replica once; peers affect only the authoritative DocumentSession. ReplaceQueued passes the branch's exact visible atoms to the existing session.replace, then applies only that generated operation to the editor branch. The branch never persists, synchronizes or generates authoritative operations. There is no positional OT.

Each request requires the current basis epoch and next sequence. Read exposes both merged authoritative source and editor-local source/sequence. An applied-but-unsaved operation advances the local branch/sequence; caller retains its optimistic draft and must Read/Flush instead of resubmitting. Rejected operations leave the sequence unchanged. End is an explicit idle point after all acknowledgements; it flushes and returns merged source, then drops the editor branch. Client adoption while new input arrives is not implemented or proved.

Authoritative replacement, branch application and sequence advancement share one synchronous Effect.try. Any throw invalidates the branch and returns AppliedUnknown through an explicit error mapper; it never leaves a retryable old sequence after possible application. Legacy handle Replace rejects an active editor basis. Effect Queue plus one scoped drain fiber sends FIFO commands. The adapter never adopts reply source automatically. After failure it keeps the full optimistic draft and dependent suffix, labeling pending records rejected, unsaved, unknown or blocked. A successful durability acknowledgement and a known applied-but-unsaved sequence are separate state fields. Recovery must reconcile against Read's matching epoch/sequence before deciding which intents remain unsubmitted; pending records are never an automatic replay list. Closing a sending RPC marks its outcome unknown, not safely rejected.

The prepared browser fixture queues eight replacements before awaiting acknowledgements, including insertion of `ab` and subsequent replacement of each new atom. A peer inserts text after Begin and before those commands. Acknowledgements are checked against the editor's local sequence, while authoritative Read contains the unseen peer contribution. Duplicate sequence fails without another insertion. Authentication loss must preserve the main local draft and pending worker edits; reconnect and End must converge through server acceptance.

The over-limit rejection fixture now uses the exported maximumActionText+1; an initial run incorrectly assumed the old 200K cap and is preserved as a harness failure. Source requests are length-checked before atom construction. The adapter proof preserves a rejected edit and its blocked suffix; scoped close keeps the recovery source available. A save-observer interruption test is distinct from actual RPC interruption and asserts an interrupted exit in the followup source.

A separate prepared permission fixture signs in an independent owner account, creates a shared workspace and writer invitation, then downgrades the worker account to reader. It checks that local durable draft and editor basis survive remote refusal, credential refresh does not restore authorization, and owner reauthorization accepts the preserved draft once. The final fixture passed after revoking the writer invitation as well as changing direct membership; grants are additive. The earlier peer actor belongs to the same account and does not prove multi-account permission behavior.

Still unproved: abrupt worker termination while queued commands are unacknowledged, actual RPC-fiber interruption, interrupted saved failure/retry, main native input and selection/caret reconciliation, latency/heap at large sizes. Source replies still clone full text. This is a correctness slice, not an instant-input performance claim.

End is unsafe as a continuous typing handoff: input submitted while End is in flight can retain the discarded epoch. The next gate must keep the old basis until the main thread conditionally accepts a merged candidate against unchanged submitted sequence, source and selection/composition generation. No such handoff is implemented here.

Run the disposable fixture with `bun experiments/worker-session/queued/server.ts` through a work-managed command. Source import locators and server entrypoint/asset paths were adapted when copying the tested outside slice into the repository. Original tested source and bundle hashes remain in results.json; this locator adaptation is not a second runtime run.
