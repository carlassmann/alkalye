**Worker safety (OK)**
- `scheduler.ts` → `client/background-work.ts` → `platform/background-work.ts` only build a `Layer.effect` and a `Context.Reference` when the module loads. `document`/`window` are touched only inside `browserBackgroundWorkLayer`'s acquire step, which the worker never builds.
- The baseline bundle already includes these modules (`worker.js:36126-36195`, pulled in through the `document-session.ts` import). So the import adds no new module-load risk in the worker.
- The worker keeps its own `BackgroundWork` from `worker-activity.ts:65`, so it doesn't pick up the DOM version.

**Scheduler propagation (OK)**
- In the bundled Effect 4, `forkUnsafe` (`worker.js:4198`) gives a child the parent's context. `FiberSet.runtime` (`worker.js:6120`) captures the current context and passes it to `runForkWith`.
- When the scheduler in a fiber's context changes, `setContext` (`worker.js:3001`) resets the dispatcher.
- Path to the handlers: the runner's `run` and the `RpcServer` fibers start inside the provided build. Per-open `Layer.buildWithScope` calls (`worker-session.ts:62,75,80`) run on handler fibers, so they inherit the scheduler too.
- Same pattern as main app: `document-session.ts:23`, `document-app.ts:145`.
- Two things stay on the default scheduler: the root launch fiber and any `Effect.runSync`, which injects its own sync scheduler (`worker.js:4284`). Neither matters here.

**Cancellation and release (correct by reading)**
- The cancel function is only called by `MixedSchedulerDispatcher.flush` (`worker.js:2277`). It runs `callbacks.delete(id)`, and a port message that arrives later is ignored. Interrupting a fiber never cancels a scheduler task.
- Release order: `nativeSchedulerLayer` is acquired first, so it's released last. Its finalizer sets `closed`, closes both ports, and re-sends pending ids through `setTimeout`. Those ids still go through the map, so an earlier cancel still holds.
- After release, new tasks fall back to `setTimeout`, which can be cancelled with `clearTimeout`. No task is lost or run twice.
