# Whole-document events experiment

The core lives in `src/shared/document-actions.ts`, `src/shared/workspace.ts`, `src/server/document-store.ts` and `src/server/workspace-projection.ts`. Files here preserve the original test and benchmark imports.

Run `bun test ./experiments/document-events/{native,workspace,cli}.test.ts`. `benchmark.ts` measures the standalone document engine; `workspace-benchmark.ts` also includes transactional permissions and sidebar projection. Run either with Bun; `BENCHMARK_ACTIONS` and `BENCHMARK_CHARACTERS` override its defaults.

A document is the consistency boundary for source, comments and anchors, replies, attachment manifests, drawings, settings and access changes. One user action can change several records atomically. Immutable asset bytes stay in blob storage; the stream records references. Workspace membership and settings need their own stream. Document metadata comes from source frontmatter; a sidebar summary is a derived projection, not another authority. [Whole-document history](../../docs/document-events.md) explains the intended opening and undo contracts.

The intended opening path is a current snapshot plus any preserved local proposals, followed by incremental synchronization. Opening never requires the historical event list. Time machine requests the history needed for its selected position. Undo creates a new authorized compensation; it must preserve peer changes and cannot restore an old permission table wholesale. Historical asset references require retaining their blobs for the supported history window. Full source compensation, historical-state UI integration and blob retention policy remain unfinished.

The downloadable snapshot contains the entire document's CRDT checkpoint, the log identity and the covered action position. The client can restore it without event bodies. History and subsequent actions are separate reads. Native Effect EventGroup, EventLog and SqlEventJournal persist validated facts; SqlSchema owns typed lookups, Crypto hashes request identities, and SqlClient supplies transactions. The action-position table indexes native journal entries without duplicating their payloads. UUIDv7 wall-clock timestamps do not determine snapshot coverage.

`WorkspaceStore` is the public Effect Context.Service for managed documents. Its Layer.provide hides the private StoreEngine, EventLog, EventJournal, Registry, SqlClient, Crypto and Reactivity. Request Identity supplies an authenticated subject and permitted actors; roles come from SQLite inside each transaction. The standalone DocumentStore facet retains trusted Principal roles for the existing document-engine fixtures. It refuses managed documents in every read and write transaction, including when a separately built fixture layer opens the same database. The managed facet now serves authenticated native Effect HttpApi routes in the real Bun application. The browser editor, legacy CLI and MCP still use the earlier workspace protocol; adopting these routes there remains in progress.

Proposals contain commit-time guards and observed register identities for permission changes, but no before-images. Committed facts contain the authenticated subject and server-derived before-images, without execution preconditions. The server validates undo against its directly fetched persisted action. Guards are never replayed. Register undo and redo append compensations rather than modifying history. A second device can undo its account's action; another account cannot claim that device's actor. Stale register undo is rejected conservatively, preserving changed comments and referenced assets. Source cancellation and offline causal undo remain open. Actions containing source changes now return a typed failure when asked for undo, preventing silently partial compensation of mixed actions.

Undo guards carry native Effect Crypto SHA-256 digests of target state, rather than the full state. Only undo actions can have guards; their targets must be distinct and changed by that action. Typed store callers are validated at each write entry point, before fingerprinting or cache lookup. Action builders compact contiguous text insertions and deletions before encoding, so ordinary large pastes stay within the same content budget. Native Schema bounds operation counts, labels, identities, field names, author names, register values and atom metadata. Text and register content share a 200,000-character action budget; expanded deletions, atom identities and before-images have separate bounds. Large edits must be split. A 50,000-character regression keeps a root-register undo under 2 KB, rejects an unseen peer edit, and preserves that edit when rebuilding the compensation.

Actor claims bind each actor to one subject and one document inside the transaction. `session.ts` derives an actor from a tab session and document through native Effect Crypto. A tab session must be a fresh identity for that tab's lifetime. Each document has its own Replica clock; editing one document cannot inflate another document's clock. Tests also ingest these streams into a combined read projection without operation-ID collisions. The production workspace-wide writer must be replaced or migrated before integration. A combined view must not produce operations.

Retries return their existing receipt before EventLog persistence. The transaction commits the action index, actor and target claims, operation identities, native journal entry and durable tip together. The first action and every hundredth document action also write a checkpoint in that transaction. A real deferred foreign-key constraint tests failure of the outer COMMIT after the native journal handler has run. Nothing remains committed and no store notice escapes. Recognized SQL defects from native transaction control become typed SqlError failures; unrelated defects remain defects. The transaction body is interruptible; COMMIT and its wake-up notice finish under a narrow mask.

Store notices use a scoped sliding PubSub with capacity one. They are wake-up hints: readers check every subscribed document's durable head and pull its tail, rather than interpreting the remaining notice as a complete event list. The stalled-reader test loses intermediate hints yet recovers both documents. Production subscriptions must preserve that contract and reconcile on reconnect. Native journal notices are private because they can precede the outer COMMIT.

History errors distinguish a changed epoch or unavailable cursor, which require snapshot recovery, from a pruned action, which cannot be restored by downloading the current snapshot. Direct undo does not read unrelated history. Retention must preserve both checkpoint coverage and the desired undo window.

Forty-one real Bun SQLite tests cover multi-record actions, cold client restoration, SQL reopening, register undo/redo replay, peer replies, journal and outer-COMMIT rollback, retry identity, staging failure, forged undo provenance and clocks, cross-document target claims, cross-device subjects, actor/document binding, bounded notices, hidden infrastructure, independent document producers and typed history recovery. Cache tests exercise a warm rollback, a separate writer killed after COMMIT, cold reopening, capacity overflow, checkpoint-write failure, covered-payload pruning and overlapping replay with pending offline edits. Native TestClock advances an actively used document across forty seconds without losing its cache. Denied and invalid proposals to forty missing documents preserve a warmed document, as do forty missing snapshot probes. Ambient transactions are rejected before publication. Deferred WAL reads remain available under another connection's write lock. Even an injected post-commit cache defect and a throwing logger preserve the receipt, notice and successful rebuild. Prevalidation rejects duplicate identities and unowned children before mutation. After 500 comment-body revisions, this fixture's whole-document snapshot is 6,387 bytes and its 502 optional native payloads total 140,805 bytes. This measures a small document whose source is unchanged, not application startup or bounded text growth.

The completed baseline used 50,000 source characters and 5,000 one-character append actions. It took 471 seconds: 92 ms median, 115 ms p95; the final snapshot was 6 MB. The first RcMap/cadence version took 105 seconds: 14 ms median, 49 ms p95. A subsequent run after Cache and read-connection corrections took 67 seconds: 13 ms median, 17 ms p95. Commit alone measured 0.82 ms median and 2.88 ms p95; client editing measured 11.83 ms median and 14.82 ms p95. Snapshot size remains 6 MB and the final database remains about 17.5 MB. Host load differs between these individual runs; the change from 105 to 67 seconds cannot be attributed entirely to the cache corrections. These are not application startup or network measurements. The baseline loaded the earlier implementation before the service refactor. The benchmark uses direct optimistic Replica.edit; the full-clone buildAction staging helper is not included in its timing and still needs a practical client-side replacement before integration.

Six completed Opus reviews support the document/snapshot architecture while retaining this slice outside production. The sixth found no correctness break in post-commit recovery, string caching, fingerprinted tips, epochs, WAL reader isolation or native cache eviction with outstanding Semaphore references. Its remaining cache findings led to authorization before lookup, uncached staging for missing documents and removing expiry during active use. Larger integration gates still include ownership transfer, asset copying between documents, offline rejected-action rebasing, ordinary deletion/reference validation, safe remote projection recovery, backup epoch rotation, atom/tombstone retention, HTTP, IndexedDB and PWA integration. Deleted bodies remain in merge state; snapshots do not erase content.

Durable tips are now separate from checkpoints. The event handler writes indexes and tips without constructing a Replica. Native Cache retains at most 32 sessions and evicts old entries without expiring an active document. Missing snapshots allocate no session. Role and actor authorization precede cache lookup; missing-document proposals stage outside the cache until COMMIT. Session lookup and insertion run with an empty Effect service context so cache fibers do not retain request principals or transaction connections. A Semaphore protects each cached session. Inside the write transaction, compare the cached log, position and proposal fingerprint with the durable tip and rebuild or catch up when another process advances it. Tail recovery checks document version counts and its final receipt position. Refreshed committed state survives rejected proposals. New proposals never mutate cached state before COMMIT. After acceptance, already validated operations update the cache; a defect explicitly clears its state and preserves the accepted receipt and wake-up notice. Periodic replacement drops transient operation history while retaining merge identities. Replica.register returns detached identities/values so comments and undo do not inspect whole-document checkpoints. The proposal digest is currently computed in both acceptance and indexing; sharing it remains a small optimization.

The store owns its write transaction and refuses an ambient transaction. Workspace/document creation now uses that same store-owned transaction boundary with deferred publication. A distinct TransactionOwnershipError rejects an ambient transaction. Snapshot/history/action reads use a separate private SQLite connection in deferred WAL mode. Snapshot JSON strings are cached per state position and serialization occurs after the read transaction closes. Cold checkpoint parsing and tail reconstruction still occur inside that read transaction; their CPU and memory costs, bulk-history decoding and checkpoint latency across documents remain to be measured.

The occasional checkpoint is intentionally synchronous in this first slice: each successful transaction leaves fewer than 100 mandatory actions after its durable checkpoint, including after a process crash. Older history is optional. A public snapshot materializes current state, so clients need no event downloads even when the server reconstructs that short tail. Checkpoint positions use global durable receipts; cadence uses separate per-document version counts. Removing full clones from applyAction relies on completing identity and ownership validation before mutation. Total tail bytes, request sizes, checkpoint compression and multi-process load still need measurement and limits. The snapshot and history routes are wired into the server. A background browser fixture verifies native Web Crypto login, typed API calls, HttpOnly session behavior, IndexedDB checkpoint restoration and logout. This fixture does not establish editor or PWA integration.

Workspace creation, membership changes and document association use native WorkspaceChanged facts in the same EventLog and writer connection. Creating a document commits its association, first DocumentChanged fact, checkpoint, claims, access projection and sidebar summary together. A deferred outer-COMMIT failure leaves none of those records or wake-ups. Retries acknowledge existing receipts after authorization; they do not reapply a past action to current state. WorkspaceSnapshot is an immediately readable projection containing owner, membership and document summaries. It uses one SQL join for summaries without loading document checkpoints or event payloads.

Workspace owner/writer/reader access is inherited by documents; the workspace owner owns its documents, and explicit document grants can add access. Only workspace owners change membership; document or workspace owners can change document grants. Removing membership removes inherited access, including for documents that member created. Explicit grants remain until the workspace owner revokes them. sharedDocuments exposes those surviving documents. Grants cannot reduce inherited access: accessRole and CLI sharing results report the effective role alongside the requested grant. Missing and forbidden document reads return ResourceUnavailable; a known reader's write returns PermissionDenied.

Document grants are root access registers in DocumentChanged, rather than another permission stream. Their SQL rows derive from winning registers. Each permission write names the register identity its author observed and must beat the current winning operation. Missing, duplicate or mismatched preconditions fail with AccessConflict. This rejects both a losing stale revoke and a higher-id stale grant that would resurrect revoked access; unrelated edits do not invalidate the observed permission register. A compensation can revoke a committed grant. Root metadata registers are rejected; sidebar metadata derives solely from frontmatter, with heading/default fallback. Summaries carry the document log and covered position, and comment-only actions advance that position without reparsing source. Public managed wake-ups contain no identifiers. Consumers must recheck durable access when pulling state.

Twenty additional SQLite tests cover inherited/granted role combinations, stale grants and revokes, legacy-facet bypass, invalid subjects, workspace ownership after creator removal and migration, effective-access reporting, simultaneous creation, failed creation and membership COMMIT, revocation before retries, source-derived summaries and cold reopening. Two CLI tests run real Bun processes with two accounts signed up through the native CLI. They exercise creation, source editing, reader grants, permission undo, inherited writers, revocation and snapshot loading. CLI sharing reports both requested and effective access. The experimental CLI derives its subject from the saved account secret through accountRoom; it ignores saved roles and rejects invented authority flags. Local OS access to the account and database files is its trust boundary. Remote CLI authentication and wire subscriptions remain future work.

Try `bun experiments/document-events/cli.ts --home /path/to/signed-in-home --database /path/to/separate-experiment.sqlite --help`. Use a separate database. Commands include workspace create/member/get/history and doc create/get/snapshot/update/share/undo/history/shared. Source input uses a file. The account can be created with the existing native `cli.ts auth signup --home /path/to/home`. No signup credentials are copied into the aggregate database.

A local managed-store run with 50,000 source characters and 200 append actions took 5.42 seconds. Client plus commit measured 26.16 ms median and 37.29 ms p95; commit alone measured 14.76 ms median and 23.55 ms p95. First snapshot serialization measured 4.54 ms, a warm snapshot 0.324 ms and the single-document sidebar 0.693 ms. The snapshot was 5,481,757 bytes. These are direct local service timings, excluding network transfer, browser restoration and app startup. Text/type/access changes currently stage a full Replica clone to produce atomic projections; comment-only actions avoid it. This is a measured performance gate before application adoption, and the 200-action run cannot be compared as an equivalent workload to the 5,000-action document-only run.

Four subsequent Opus workspace reviews found two permission races and a fixture bypass. The final focused review confirmed that observed-register preconditions resolve stale grant resurrection; it checked multi-field batches, unrelated higher clocks, creation, undo, replay and receipt behavior by reading the code. It did not run additional probes. Regression tests now cover each counterexample. The old fixture facet refuses managed rows in its actual transaction. Native CAS preconditions protect permission intent independently of Lamport/actor ordering. Guards are execution conditions, while receipts acknowledge immutable accepted facts. Later retries cannot reapply an old grant after revocation. A client must rebuild a permission action from newly observed state after a conflict, rather than silently patching its guards. Final full verification passed 440 tests with four existing frontmatter TODOs. The long browser-checkpoint CLI fixture now has a twenty-second case deadline; each CLI child has a ten-second deadline and owned cleanup, preventing its earlier five-second timeout from leaving a continuation between tests. Additional follow-ups include native SQLite busy waits between independently built writer layers, request-size/tail bounds and scoped wire notifications. Production must build one writer layer per database; the experimental fixture is not a parallel writer adapter.

The managed server now stages ordinary source/type/access projection changes in its private gated replica. Failed COMMIT, cancellation, defects and failed recreation discard that cache before releasing the gate. Checkpoints still restore a copy every hundredth action. Matched isolated 50,000-character/200-append runs reduced median commit from 13.16/10.98 ms to 7.02/7.13 ms, with identical snapshot and database sizes. These timings exclude browser startup, network transfer and buildAction staging.

The browser session in `src/client/document-session.ts` is retained without main application callers. Native EventLog/IndexedDB persists the initial snapshot, exact proposals and authoritative incremental pages; native Queue preserves failed optimistic saves in order. Text preflight rejects permanently invalid changes before changing source or clock, so later valid edits remain writable. Cached reopening needs no HTTP history. A random actor per acquisition prevents duplicated-tab identities. Opus reviews exposed poisoned history and dropped optimistic edits; the received-page ownership overlay and ordered save queue address those cases. Real browser checks include the existing editor, injected IndexedDB failure, retry, offline reopening, simultaneous sessions, lost receipts and typed epoch recovery. Native HttpApi history limits pages to 1–1000 actions, defaulting to 100. Direct trusted store and CLI history reads retain their existing full-history behavior. Main UI migration, explicit Reset/Rejected flows, offline creation, background sync and batched editing/large deletion encoding remain open.

`session.change(label, build)` stages a whole-document command against the durable replica. Its callback receives an isolated replica; deriving source changes from that staged state preserves concurrent optimistic typing. A fresh native Crypto actor identifies each command. A native Ref retains the proposal when the same Effect runs again, so retry preserves its author, label, guards and operation identities. Creating another change Effect creates another intent. The journal append is the save boundary; subsequent projection or notification failures require cache recovery and cannot turn that append into an unsuccessful save. New permission proposals compare their observed registers under the journal's Web Lock. A stale local grant returns typed AccessConflict before entering the outbox; retry retains its original guards, and an explicit new intent observes current state. An already saved proposal keeps its immutable receipt even after later permission changes. Public commit only verifies an already saved exact proposal; new producers must use change. Waiting for a journal lock stays interruptible; retry reconciles a proposal that might already have been appended. Network rejection of an earlier pending action still needs explicit recovery.

The public session replica is a frozen read facade. Fields, metadata, document records and exported checkpoints are detached; tracked visible atom arrays and their atoms are frozen while retaining the editor's existing source-view contract. Pending actions are frozen, and failure/revision streams expose no writable subscriptions. Optimistic input publishes a view revision immediately. Builders must use their staged replica. `tests/document-actions.test.ts` checks isolated actor allocation and failed builder isolation. Generic staging still copies the whole checkpoint and allocates one server actor claim per command.

Save, projection, snapshot-copy and notification failures have independent frozen state. Native dropping Queues own scoped recovery workers, with capped jittered exponential Schedules for transient IndexedDB errors. Typed drafts retry while idle without another edit. Recovery observes its starting failure inside the native Semaphore that protects its work. Corrupt data and typed conflicts require explicit attention. A successful replay cannot clear a snapshot quota error; an older recovery cannot clear a newer failure. Snapshot capture requires a completely replayed projection. Capture holds the editing gate; IndexedDB copying runs outside it. The cache transaction still verifies the exact covered journal receipt and monotonic position, preventing a deleted cursor from repopulating the cache. A synchronous beforeunload listener protects queued source and in-flight commands, and clears when local persistence completes. Session release ends its native source Queue before stopping background workers and draining drafts. New edits and command builders are refused while closing. Its final flush retries transient errors three times; exhaustion fails release observably and retains queued drafts and source for inspection. They remain in memory, retain their navigation guard, and a closed journal cannot persist them. A UI must flush successfully and check unsaved/save failure before releasing, or explicitly preserve the draft through another recovery path. Durable storage or a blocked journal lock can still delay release.
