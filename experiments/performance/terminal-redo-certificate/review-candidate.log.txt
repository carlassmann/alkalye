**Logic: no blocker found**
- **Clearing the slot:** happens inside the commit closure (`:628`) before the visibility commits and before `operations.set`. It uses the same `has` check, without dedupe. `validate()` never touches the slot.
- **Restore:** clears as the first statement (`:1527`), before the cooperative throw and before any `yield`.
- **Fork:** copies the slot last (`:164`). `forkEffect`'s generation and clock fence covers a stale copy. The fork's `textCache` goes through `immutableAtoms`, so the fork probably misses the slot and takes the slow path, which is safe.
- **Publication:** requires canonical last === raw last, the frozen check, and none of the structural flags.
- **Redo:** looks up `atomIndex` by identity, so the splice appends the same object to both views.
- **Lazy cache refills:** `visible`, `text` and `textEffect` only refill a cache after `invalidateText`, which only a new op triggers. So exact identity on all three caches is a sound guard.
- **Undo path doesn't catch a Redo:** a Redo cancels an Undo, which is not a text op, so `prepareTerminalCancellation` returns undefined first.
- **`textOwners` / `known` guards:** unreachable while the slot is live, because only restore produces compacted ids and restore clears the slot. They are fine as defence in depth.
