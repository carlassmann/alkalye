# Forward Chunk splice experiment: HOLD

Production unchanged. The candidate assembles sorted multi-replacement output from slices of the original Effect Chunk, rather than repeatedly slicing a mutated sequence backwards. Empty, single and unsupported ordering retain the original path. No custom tree or new dependency.

Strict types and 84 public tests passed, with 957 assertions. Tests cover Unicode, CRLF, boundaries, repeated concat-backed edits, immutable forks, reconstruction, causal Undo/Redo, mutable operation input, frontmatter and source fences. Two real SQLite DocumentSession cases apply 512 replacements from a stale basis after a peer commit, then flush, decode, reopen and Undo. Initial failures were fixture errors: ReadonlyReplica requires forkEffect, buildAction requires an operation array, and the outside copy lacked build.ts. Corrected logs and first failures are retained.

Twelve native EditorElement cells passed replacement-count, exact source, primary caret, independently accepted edit and durable Undo gates. Both arms use frozen 1b630c8 backend; only candidate client atom-sequence.ts differs. Per-cell stopped database resets use one snapshot of the already-existing generated fixture history, and profiles clone one closed seed. Trials alternate arm order. Entry hashes were checked through the driver. Loaded script names are retained. This is not a main-versus-rewrite comparison.

Full beforeinput-containing RunTask medians: 512 cursors 14.875→14.538 ms (max 15.120→15.072); 2048 cursors 32.884→32.647 ms (max 33.114→33.036). Whole three-second window peaks: 512 median 15.120→15.072, max 15.761→15.120; 2048 median 58.170→56.986, max 58.340→58.075. Layout, Paint and GC remain mixed. These three samples per arm do not establish a useful gain, a percentile, a heap benefit or 120 fps. Undo was validated after the recorded window; its latency is unmeasured.

Important attribution correction: the earlier 2048 Chunk.drop inclusive 8.862 ms counted recursive occurrences of the same frame repeatedly. Deduplicating frame keys within each sample gives 1.226 ms unique-stack inclusive and 0.466 ms self. At 512: 1.741 ms recursion weighted, 0.319 ms unique inclusive, 0.003 ms self. Retained parent stacks identify replaceAtoms→cachePreparedText, but the former 8.862 ms bottleneck inference is withdrawn. The candidate ordered branch has not yet been counted in the actual timed application. A separate untimed mechanism gate is pending; the data does not prove this design ineffective.

Both readonly Opus reviews completed. No semantic blocker was found. Final review rejects the earlier speculative quadratic-growth claim and supports HOLD. Two review statements need correction: the Session test explicitly executes 512 value.replace changes, and observed sample intervals are around 150 microseconds rather than the review's assumed one millisecond. Public input aliasing matches existing Chunk behavior; no new ownership guarantee is claimed.
