**Concrete blockers**
1. **Make the append check structural.** Require the prefix and `window.start` to be unchanged, and only then `value.startsWith(previous)`. Real docs with repeated text (blank lines, boilerplate) can hit the same false match.
2. **`detail` is 0 on pointerdown.** The pointer-down traces log `detail: 0`, so `:167` (`event.detail !== 1`) is always true and the guard never fires. That confirms the prior review's blocker 2.
3. **Prior blockers 1 and 3 are unchanged.**
   - `:912` still forces `forward` when the selection is neither backward nor forward. That drops the word on a double-click drag upward, and the anchor on a fast first move.
   - `:911` still tests start/end instead of the moving end.
4. **Hidden drag affinity isn't observable,** so word granularity and shift-click remain open.
   - `setSelectionRange` likely resets word extension to character extension.
