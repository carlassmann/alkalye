# Document persistence interruption boundary

Public DocumentSession plus a transparent DocumentJournal/EventJournal adapter, real Bun SQLite client journal and independent WorkspaceStore transport. Deferred barriers hold before or after the actual journal `withLock` returns. No production hooks, replacement journal, fake clock or masks. The original two cases passed 20 assertions; the strengthened probe passes 36 assertions and strict types. Sources and logs remain outside as well as this archive.

Before commit: interruption leaves the edited source intact; sync and cold reopening retain it, and the accepted position does not advance. After commit: the interrupted caller initially sees the edited source, but replay/sync/cold reopening recover exactly one Undo. The accepted position advances once; repeated sync adds nothing. The strengthened probe asserts an interruption-only Cause and the immediate edited view. A separate cold session opens before the original caller flushes or syncs: it recovers the local Undo and its exact undoOf identity while the server position remains unchanged. Final server lookup verifies that exact recovered action ID and undoOf; repeated sync adds no action. These checks establish the local/durable boundary, not physical paint or complete worker recovery behavior.

The first probe paused after `write` but still inside SQLite's outer `withLock` transaction. Its assumed post-commit outcome failed because interruption rolled the transaction back. That invalid assumption and the initial unused-import type failures are preserved outside; their paths, sizes and hashes are retained. The corrected probe pauses after the enclosing lock returns. No uncertain mutation was repeated: each case has a fresh temporary store and client directory.

An interrupted fiber is not proof that a committed action was unapplied. Callers must retain unknown-completion identity and reconcile before retrying. Experimental Worker UndoQueued source classifies interruption as unknown; its end-to-end behavior at this exact boundary is not yet proved. Opus accepted the original outer-transaction boundary and unknown-completion policy, requesting stronger local cold-reopen and action-identity assertions. Those assertions now pass; Opus accepted the strengthened probe. Browser/RPC restart, process-crash durability, retry-after-unknown and peer/multi-token cases remain unproved. The regular integration test permits the post-commit view to have already recovered through periodic replay; it still requires the exact durable local action and one server acceptance. No production persistence change adopted.
