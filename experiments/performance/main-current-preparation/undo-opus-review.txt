## Blockers
**B1. Undo timing starts on the Meta key, not on z.**
- `arm` (`:366`) starts timing on the first trusted keydown, and `press Meta+z` sends Meta first.
- So the start mark, the enclosing task and the 3 s window are anchored to the Meta keydown, not the Undo task.
- Fix in `arm`: keep logging every event, but only set `start` when the key isn't a modifier:
  `state.events.push({...,key:event.key,meta:event.metaKey,ctrl:event.ctrlKey});if(!state.start&&!['Meta','Control','Shift','Alt'].includes(event.key)){...}`
- After `:618`, assert that a z keydown with the platform modifier was seen:
  `window.interactionProbe.events.some(e=>e.type==='keydown'&&e.key.toLowerCase()==='z'&&(e.meta||e.ctrl))`

**B2. Stale traces can be summarized as new results.**
- Trace names are fixed (`:428`, `:433`), `output` is reused (`:80`), and `summarize.py:31` reads any file that exists. An old Undo or input trace would be read as this run's.
- Fix after `:80`: `if (await Bun.file(join(manifest.output,"results.json")).exists()) throw Error("Fresh output directory required")`

**B3. Partial Undo evidence is lost on failure.**
- The `catch` (`:660`) only fills `observation`, so a timeout at `:614` or `:618` drops the Undo probe.
- Also, `undoTrace` is reported whenever `mutated` is true (`:650`, `:676`), even if the Undo trace never started.
- Fix: add `let undoStarted=false`, set it to `true` right after the `:606` profiler start, and report `undoTrace: undoStarted ? undoTrace : undefined`.
- In the `catch`, add: `if (undoStarted) try { undoObservation ??= evaluate(session,"(()=>{window.interactionEventObserver?.disconnect();return {probe:window.interactionProbe,network:window.interactionNetwork}})()") } catch {}`

**B4. Main's per-trial session uniqueness isn't checked.**
- `profile()` ignores the count of removed `co_…_N` keys (`:234`), and nothing checks that a new Jazz session was created.
- Fix: for the original version, require removed ≥1.
- After the ready wait at `:459`, read `Object.entries(localStorage).filter(([k])=>/^co_[^_]+_[0-9]+$/.test(k))`.
- Throw if any value is in a run-level `Set` (seeded with the values just removed), add the new values to the set, and store them in the result.

**B5. History keeps advancing, but the ready gate can't see sync catch-up.**
- Each cloned profile has the seed-time local state. The server has the seed plus every earlier x/Undo pair, including the ones from the input-only smoke.
- The ready gate is a content-hash match, which stale local state also passes. So catch-up sync traffic can land inside either trace window.
- Minimal fix: in `interaction-matrix/network.js`, count incoming socket messages (`observed.received=0` and a `message` listener).
- Copy that count into the probe at `start` and `end`, and report both. Rewrite's long-poll counts are already there.
- Label each row `history: "advancing"` with the number of accepted pairs before it for that key. Don't claim identical history; the README line 27 wording is correct.
