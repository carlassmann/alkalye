# A whole document, one history

A document's source, comments, replies, attachment references, drawings, shared settings and access grants belong to one event stream. A user action can change several records in one transaction. Attaching an image can add its manifest and insert its source reference together; neither change can commit alone.

Frontmatter remains authoritative for document metadata. The sidebar stores a derived summary, with the document position it covers. Workspace membership has its own stream because one membership change governs many documents. Presence, cursors and playback progress are transient messages, not durable document actions.

## Opening and history

Opening reads a current snapshot containing the document identity, log identity, covered position and complete CRDT checkpoint. The checkpoint retains identities, clocks, anchors and tombstones needed to merge concurrent changes. Restore that state and preserved local proposals, render, then synchronize changes after its position. Cached opening requires no network.

The client does not download old event bodies to open a document. Time machine fetches history separately. Historical reconstruction uses a checkpoint at or before the selected position and the following retained events. A checkpoint after that position cannot reconstruct an earlier version on its own.

The snapshot is a derived copy of accepted events. Its covered position advances with its state; acknowledging a position without its corresponding state would lose edits. Local proposals stay separate until the server acknowledges their exact identities. Retries preserve those identities.

The browser's `document-local-state-v3` cache stores an accepted-only checkpoint, its remote cursor, exact ordered pending actions and rejected proposal records. Reopening restores accepted state and reapplies only pending actions locally. Unsaved editor drafts remain in the session's separate queue. A document created offline has an empty accepted checkpoint until publication acknowledges its original creation. Two tabs receiving that publication cannot apply the accepted creation twice.

The cache also covers a local journal position, so subsequent opening reads only that journal's tail. Migrating a v1 cache checks its identity and reconstructs accepted state from the retained local journal once, then writes v3 at the same position. A valid v2 cache restores directly and is rewritten as v3. Migration requires no remote snapshot or historical download. Invalid derived state, including a pending receipt without its action, triggers full local replay and a repaired cache. Missing journal positions still fail visibly; a cache cannot prove that its underlying events remain intact.

A snapshot requested before another tab records an offline creation cannot overwrite that creation when its response arrives late. Publication acknowledges the creation's exact identity, then merges newer accepted events. A delayed duplicate publication cannot move the accepted cursor backwards.

Keeping history optional removes its download cost. It does not make snapshots free: checkpoint size, decoding and restoration still need measurement on realistic documents and devices.

The server persists a full checkpoint every 100 document versions. A cold server can replay up to 99 later actions before returning the current snapshot; the browser receives the resulting state rather than those older bodies. Retention must never prune this required tail. It must first persist a newer checkpoint, or prune only events already covered by the saved checkpoint. No retention worker currently enforces that rule.

## Undo is another action

Undo appends a compensation for an accepted action. It never erases events or replaces the current document with an old snapshot. A compensation must preserve intervening peer changes and pass current authorization.

The shared planner now compensates text, comments, attachment manifests, drawings and settings together. It stages text cancellations first, then restores only registers still owned by the original action. A created or restored record with peer changes is preserved as a whole, even when a peer now owns its type. Accepted restorations retain the earlier register identities, allowing redo of a plain deletion without mistaking inherited fields for new peer work. An intervening peer write is detected even when its clock predates the restoration. Old restoration facts without that provenance refuse the whole compensation. Attachment references are compared by complete identity in the resulting source; a peer reference preserves the whole manifest. New proposals need no target hash guards. Legacy guards remain checked when present.

The native editor routes keyboard undo and redo to its document session. The session indexes local proposals and accepted receipts only when undo is invoked, in pages of 100 bounded by the journal position already replayed. A normal opening does not read this history. Accepted actions use their canonical server beforeimages. Pending actions derive a provisional basis from accepted state and preceding pending actions; that prediction is not stored or admitted as an accepted fact.

Effect Graph follows compensation chains, including same-account receipts from another device. Local document creation is excluded. New normal actions invalidate older redo branches. Definite rejected compensations remain in the journal but leave the active chain; a rejected provenance boundary excludes that root. An ambiguous older chain or a fully overwritten contribution cannot block an independent eligible undo. An unavailable action is reported without appending a compensation.

Each command keeps its prepared target and identity across failed writes and interruptions. Concurrent commands serialize selection in one session. Effect EventLog's existing journal lock replays and checks for an active successor before appending, preventing two tabs from adding compensations for the same tip. New source input while a command waits to prepare makes it stale before append. The editor suppresses overlapping keyboard requests; its document scope owns cancellation.

A cold offline reload reconstructs the branch from retained local facts. This first undo still reads the complete local journal in bounded pages; a persistent recent-action index and realistic latency measurements remain needed. Typing currently creates one action per input event. Register compensation also needs restoration provenance for natural successive undos of edits to the same setting: restoring an earlier value under a fresh register identity does not yet restore the earlier contribution's eligibility. These limitations are not resolved by event sourcing alone.

Text requires causal cancellation of the original insertions and deletions. Restoring an old source string would overwrite concurrent work. Event sourcing supplies provenance and replay; it does not supply this cancellation algorithm automatically.

The causal cancellation experiment now compares two independent visibility implementations against real `Replica` edits. Its 35 tests cover overlapping peer deletions, insertions inside cancelled text, undo/redo branches, cold snapshots and frontmatter creation, removal and concurrent key edits. Two hundred seeded graphs exercise mixed insertions and removals from three concurrent actors. A further 100 seeded real-edit sequences undo and redo the latest change back to its exact text and atom identities, interleaving earlier cancellations and cold restores. A 20,000-step cancellation chain uses iterative evaluation. These model tests exercise the production text replica. Native document acceptance now permits causal cancellation only as verified compensation for a retained, authorized action. Legacy encrypted room packets continue to reject cancellation.

The experiment infers insertion ownership from atom identities and retains deletion attribution and cancellation edges in snapshots. Snapshot restoration merges existing facts, rejects changed identities before mutation and preserves a replicated migration floor. Legacy deletions remain permanent; undo below that floor is unavailable because the old checkpoint lacks attribution. Native acceptance rejects new text actions at or below the floor. A low clock alone does not prove that an operation was covered by a legacy snapshot. Compatibility replay still folds below-floor deletions into permanent marks; an offline legacy operation can therefore remain outside causal undo. Canonical native cache migration and recovery must preserve pending proposals explicitly. Receiving the floor before or after cancellation facts produces the same state. Production must fix that floor on the server during migration, before accepting any cancellation; raising it later would silently reverse older undo. Legacy deletion owners cannot exceed the floor. Production checkpoints now use `alkalye-state-v2` for that provenance. This CRDT snapshot version is separate from the browser cache version described above.

Native acceptance rederives the whole compensation on current accepted state. Extra changes, omissions and duplicates are refused. Text contributions need retained ownership above the migration floor; ineligible text refuses the entire mixed undo. Inactive contributions can be skipped, and an empty plan returns a typed failure. Cancellation preserves peer insertions and overlapping peer deletions, including through redo and cold snapshots. Current permissions still govern acceptance. Existing cached clients need an explicit upgrade path before broad rollout.

Production regression tests exercise cold undo and redo without historical operations, overlapping peer deletions, preserved peer insertions, immutable insertion and removal ownership, deterministic legacy undo hints and unchanged revisions when old history is hydrated into a migrated checkpoint. The session preflights all affected replicas before applying changes. Legacy undo hints point strictly forward in clock order and choose the same winner when concurrent undo restores one atom twice. Those hints still track one restoration only; concurrent legacy inverses can leave duplicate characters that a later legacy undo does not remove. Native causal cancellation retains original identities and avoids this restoration-hint policy. Incoming batches preflight all new operations before journaling, so a conflicting covered contribution cannot persist its valid prefix. Native document-action cancellation is now accepted and replayed by the browser session. Archived identity protection and explicit packet recovery still need work.

Each accepted action can be compensated once. The durable chain index prevents undoing the original again after redo, which could otherwise compensate text while skipping registers now owned by the redo. The next undo must target the latest action in that chain. Byte-identical retries return their original receipt even after later compensations. The startup migration backfills retained edges in pages of 100. Verification preserves existing edge identities and raises the undo boundary to the latest conflicting legacy compensation, including in stores with an older index. Legacy forks follow the persisted branch; retained actions above that boundary remain individually compensable. Pruned bodies cannot establish whether another legacy branch existed. Missing or undecodable historical bodies conservatively disable undo below their document boundary without blocking a usable current snapshot. Damaged historical bytes remain stored. The browser now retains definite rejection facts and withdraws their exact identities before independently publishable work continues.

`GET /api/documents/:document/actions/:action/chain` discovers the latest compensation from indexed receipts, without reading event bodies or reconstructing document state. Current read authorization and lookup share one SQLite transaction. The result includes the log, latest action position and chain depth. It survives pruning and restart; missing successor receipts, backward edges and cycles fail visibly. If migration cannot prove the discovered tip is complete, lookup returns `BelowFloor`; an older starting action can still lead to a verified tip above that boundary. The response's `from` is the requested starting action, which may itself be an undo or redo. Discovery does not promise undo eligibility: the client still needs the latest action's retained body, and acceptance checks its provenance and current authority. A tip can advance between discovery and submission, producing a typed `Superseded` rejection. Normal document opening never requests this endpoint.

Access changes belong in history, but content undo or historical restoration must not reinstall historical permissions. Explicit permission-only actions remain compensable under current owner authorization and exact permission-register guards; this preserves owner grant/revoke undo. Mixed content actions retain current permissions. A revoked writer cannot recover authority through undo. Workspace access governs the document independently of its historical content.

Snapshot and history downloads require current read access. Revocation stops further downloads; it cannot remove copies already cached by a former reader. Redo must also preserve intervening peer changes. Mixed undo/redo tests preserve peer insertions, deletions, replies and referenced manifests. Historical blob retention remains unfinished.

The native `GET /api/documents/:document/actions/:action` endpoint now retrieves that one accepted action and its beforeimages through Effect HttpApi. Its indexed read checks current authority in the same SQLite read transaction. Readers may fetch retained history; missing or unrelated identities stay unavailable, and pruning returns `DocumentHistoryUnavailable` with the exact affected action. HTTP tests compensate a fetched register action after snapshot reopening count zero historical-page requests and prove a retained action stays readable when preceding history is pruned. A fresh server restores the current snapshot from SQLite after that pruning. HTTP tests now undo and redo mixed source, comments and chunk manifests using snapshots plus individual actions, with zero history-page requests. Browser tests verify receipt replay and offline reopening of those compensations. The native session now produces undo and redo from its local journal.

## Assets and retention

Events contain immutable blob references, not repeated image or video bytes. Snapshots contain the manifests needed for current state. Blob storage serves the bytes separately.

The native attachment producer stores verified chunks durably before appending one manifest-and-source action. A multi-file selection stores every file first, then commits all manifests and source references in the chosen order as one action. A failure preparing a later file leaves no partial document action; already stored orphaned bytes still need cleanup. Synchronization publishes a new document first, uploads its missing chunks, then submits that action. Incoming uploads are digest-verified; acceptance checks their presence and declared sizes in its transaction. Read-time verification detects later corruption. Retrying the same producer retains its exact action identity; a failed byte transfer cannot commit half the attachment.

Browser caches store native Blob parts, scoped to the account and document. Downloads re-read their saved parts from IndexedDB before assembling the file. Reads verify their digests; a corrupt local copy can be replaced with verified server bytes. A corrupt server read removes only the observed corrupt copy, allowing a later verified upload to repair it. Missing-chunk queries require write access and compare declared sizes with stored lengths and binary types without hashing file bodies. Document, owner-account and server quotas count retained bytes inside the upload transaction. Transfer deadlines scale with size and remain interruptible.

Missing bytes, corruption and exceeded quotas have distinct typed failures. The selected document exposes its synchronization failure while keeping local editing available. Restoring the original bytes can unblock the same queued action. Full recovery controls and cleanup of unreferenced uploads remain unfinished.

`DocumentAssets.restore` requires current write permission and an attachment in the same document. A deleted attachment remains recoverable when its creation is still pending, so attaching and then deleting a file cannot strand its queued upload. Recovery verifies the selected file against the existing chunk digests before storing each chunk; file names and MIME guesses do not replace the immutable manifest. Wrong size, different content and reader recovery fail without appending a document action. Restoring the original file allows the same pending action to synchronize. Repairing an already accepted attachment still needs an explicit re-upload path in the UI.

`DocumentMedia` acquires object URLs through Effect's RcMap. Each render scope retains its own references; releasing one render cannot revoke another render's URLs. A failed lookup or defect releases its child scope immediately and leaves healthy previews available. Restoring bytes allows an immediate retry. Closing the document scope releases all URLs. Only image, audio and video attachments produce preview URLs. The entire declared MIME type must contain printable ASCII; preview bytes use a normalized base type. SVG previews use native image decoding and canvas to produce PNG bytes. Preview preparation preserves the original bytes and manifest. HTML attachments have no preview URL.

The native controller connects the file picker, paste, drop, inspector and preview/presentation renders to that producer. Downloads read stored bytes, including original SVG bytes rather than the raster preview. Reader views hide mutation controls; the producers also enforce permission. Muting records an audio/video register change and patches the existing media element, preserving playback.

`DocumentMediaView` holds one FiberMap worker per immutable reference. Unrelated edits and added attachments cannot restart a pending download. Retry replaces only failed workers. Workers publish results through SubscriptionRef; the controlling stream renders before removing unused workers, so a worker cannot wait for its own interruption. A failed DOM swap retains old and new leases until a successful render. Hiding or closing clears media DOM before releasing URLs. Real browser tests restore manifests, verified bytes and mute state offline without downloading historical actions. Upload-recovery controls and print-specific media scopes remain unfinished.

One journal does not require one permanently blocked queue. The current implementation still stops at a failed proposal; explicit rejection, quarantine and recovery must let independent later edits continue without falsely acknowledging a rejected action. Undo authorization checks both current document grants and workspace membership. A document journal alone cannot reconstruct historical workspace access.

The client validates text causality before journaling a proposal, and native acceptance checks again before committing: each insertion anchor and deletion identity must belong to the same target's preceding state or this action's inserted atoms. Tombstoned atoms remain valid anchors. Unknown identities return `CausalDependencyMissing`; own insertion cycles fail as document conflicts. Registers co-written with invalid text roll back too. Frontmatter `order` and `deleted` metadata contain key names, not atom identities.

Compatibility room packets have separate admission rules. They decode newly observed ciphertext even when a cold checkpoint already represents its operation identity. Immutable conflicts are isolated before storage, while healthy neighboring packets continue. Effect's semaphore serializes receivers; a local edit during persistence causes revalidation and quarantine rather than a defect. A generation check stops retries when an unexpected apply failure occurs without a concurrent state change. Quarantine preserves each rejected byte version under an Effect Crypto fingerprint and removes only matching active or archived copies. A stale observation cannot delete repaired bytes, and quarantine itself leaves outgoing receipts intact. Explicit history archives admitted packets only. The CLI preserves the exact raw row in its existing recovery table, so later relay repair can replace only that observed version. Causal cancellation is refused in this protocol; it belongs in authorized document actions.

Outgoing selection uses Effect Stream to read bounded pages and select up to 80 packets. It skips the exact quarantined byte versions by fingerprint. Their receipts remain stored and visibly pending for recovery. Corrected ciphertext under the same operation identity can synchronize without deleting the rejected version. Explicit recovery controls remain unfinished.

A blocked outgoing receipt currently prevents ordinary synchronization completion and room compaction. Keeping its bytes is necessary, but keeping it in the transport queue is still a limitation. Recovery must separate that receipt from independently publishable work without acknowledging or discarding the failed change. Outgoing reads hold an Effect semaphore and recheck their captured socket before sending, so reconnecting during selection cannot send through an unjoined replacement.

Failed key imports and unexpected cryptography failures preserve the whole batch. A batch with no authenticated packet needs a fresh successful decryption before any ciphertext can be quarantined. After a cold local checkpoint open, that witness may come from stored active packets, archived history or the sealed relay checkpoint. The sealed checkpoint commits atomically with its derived state but occupies a separate row, so normal state reads do not clone its bytes. Later local compaction preserves that witness. Effect Stream reads bounded pages and stops at the first authentic packet. This exceptional recovery path can read older bodies; normal opening still does not replay or probe history. Wrong keys cannot authenticate that witness and leave cached bytes intact.

Real browser tests cover cold snapshots, same-batch and concurrent forks, persistence races, interruption, multiple rejected versions, witness recovery across archive pages and reopening. Rejected outgoing packets still need explicit recovery controls. Cold snapshots retain winning registers rather than every old register identity; admission and compaction must also protect the corresponding archived bodies from changed copies.

The shared text dependency classifier uses Effect Graph to separate ready operations from deferred operations and propagate missing insertion, deletion and cancellation dependencies. The admission planner expands compact wire runs and validates immutable identities before classifying dependencies. It rejects cycle members and references to atoms in another target, then reclassifies their dependents as deferred. Independent healthy operations remain ready. Planning never mutates the replica, and its results preserve the original input objects so callers can identify their exact stored packets.

The native action guard uses this classifier strictly: an incomplete action fails before journaling, including its co-written registers. Model tests apply only the ready partition, parse that resulting snapshot, restore the missing baseline and promote the preserved suffix. One hundred and fifty seeded offline-writer sequences converge with their full-history oracle; another fifty deliver cancellation and redo tails in small pages before restoring their baseline. Closed operation groups can commit together when their atom graph is acyclic. Duplicate operation edges and missing starts are suppressed; normally ordered atom references avoid constructing a second graph.

Browser and CLI compatibility replay now use the admission planner. The browser durably stores deferred ciphertext even when a history page requests no ordinary persistence. Deferred packets remain outside the replica and its compacted packet set. Opening restores the accepted checkpoint and decodes the remaining tail, without replaying archived history. Arrival of a predecessor, a local save or another tab's checkpoint can promote that tail. Conflicting optional cache checkpoints cannot replace accepted identities or abort healthy admission. Admission reserves observed clocks only after durability, so a reused actor cannot reuse an identity from its deferred tail.

Local compaction continues with complete accepted state while deferred packets stay active. Relay checkpoint publication waits for all dependencies and rechecks the captured generation and cursor after asynchronous sealing. Deferred work preserves the publication request across cold opening. A relay reset reuploads its surviving bytes before a later predecessor can promote them. Loading those bytes does not claim that history is complete. Live history views refuse incomplete state, and the CLI disables edits and checkpoint-repair completion while dependencies remain missing.

Real browser tests exercise IndexedDB, relay reset, checkpoint suppression and resumed publication, cold opening with one deferred decryption, cross-tab promotion, interruption, repaired owners and preserved outgoing receipts. Conflicting copies of an unaccepted deferred identity retain the first observed copy; later arrival alone cannot prove which copy is authoritative. That case still needs explicit recovery.

Incoming history validates the entire batch against accepted state and earlier actions in that batch. Pending local atoms cannot legitimize an unaccepted fact. A malformed suffix rejects the batch before its valid prefix is journaled.

Native synchronization can quarantine a definitely stale compensation or conflicting permission-only proposal. Effect Graph follows whole-action dependencies through text contributions, record creation, permission observations and compensation references. Rejection preserves each original proposal, journal identity and typed failure. Accepted state is unchanged; the optimistic view is rebuilt from accepted state, independent proposals and unsaved drafts. The editor always derives input from the atoms actually displayed, including during IME composition, so this rebuild cannot silently repeat the rejected change.

Rejected proposals are withdrawn in their original order, interleaved with independent commits. A native `DocumentWithdrawn` event permanently reserves their operation identities and clocks for the authenticated account and document. It changes no source, registers, permissions, snapshot cursor or visible history. This accounts for clock gaps without rewriting later proposals or relaxing admission limits. New withdrawals require a current writer; an exact retry remains available to a current reader. Lost responses retry the same bytes. An accepted receipt received before withdrawal can settle a rejected proposal; acknowledged withdrawn identities can never appear in accepted history.

The cache encodes typed failures as plain data before IndexedDB persistence, validates rejected bodies against their journal proposals and retains withdrawal acknowledgements. Cold reopening uses its covered journal position and does not resubmit acknowledged withdrawals. Network failures and access revocation preserve pending work. Automatic quarantine refuses closures containing inserted text; mixed permission failures, those inserted-text closures and explicit recovery controls remain unfinished. Withdrawal payload retention and account storage limits still need a policy alongside ordinary event retention.

Removing an attachment from current state does not make its blob disposable. Retained historical states, undo, and pending offline work can still reference it. A retention policy must account for those references before deleting bytes. If an old action or blob has expired, history must report that explicitly.

Deleting content from the current document leaves its older events intact. Permanent redaction needs a separate policy covering historical checkpoints, events and blobs; it is not implemented yet.

Browser tests exercise actual tabs, reader/writer changes, revocation and storage failures. The sidebar summary is a derived copy; downloading old actions is unnecessary for opening.

The default app, CLI and MCP use this protocol. Personal-workspace documents can be created and edited offline, then reopened from their own journals. A scoped background drainer publishes closed documents without selecting them. Exact creation identity, workspace and subject live in the journal; publication binds the accepted log and removes only the matching creation proposal. Later edits remain pending until their own receipts arrive. A failed response retries the same intent instead of creating another document.

Separate dirty markers discover pending work. Appending a proposal and clearing its marker use the same document Web Lock; clearing first replays the journal and checks for pending actions and queued source. Source-derived sidebar copies advance monotonically through atomic IndexedDB updates. A failed copy can be rebuilt from durable state. Creation locators stay until the current remote catalogue is cached successfully, so a failed cache write cannot hide an accepted document on offline reload.

Sign-out blocks further requests and editing while preserving cached content for local reading and export. Access errors stop that session's synchronization until it is reopened. Network deadlines bound remote work; changing the selection cancels an unfinished lookup while cached documents remain available. Native comments now use the same document session: creation, replies, resolution, reopening, deletion and comment settings each append a document action. Selection anchors come from the editor's current CRDT characters and survive intervening source edits. A draft retains one comment or reply identity across failed submissions; changing its body stages a new action, and retrying an unchanged body preserves its exact action. Reader views keep discussion and source navigation but hide mutation controls. Per-document scopes own submissions and close their dialogs on navigation. A late callback cannot close a replacement dialog or report that another document was saved.

Closing a comment dialog cancels its pending submission. Browser tests hold the document's storage lock, submit a reply and press Escape; releasing the lock produces neither a saved reply nor a stale failure message. Cancellation cannot retract an action that has already committed.

Comment ranges share one source-position index per revision. Empty discussions skip the scan. The component retains its own scoped CSS and renders quoted source and reply text through escaped markup. Assets, drawings, document themes, workspace permissions and time machine use the same document session.

ZIP backup and import, invitation and public links, and folders on the device now build on this session; [portability-sharing-and-folders.md](portability-sharing-and-folders.md) describes them. Invitation memberships and document moves are workspace facts in the same journal. Complete rejected-action recovery controls and four concurrent frontmatter cases remain unfinished. Event sourcing supplies durable facts and reconstruction; it does not implement product flows automatically.
