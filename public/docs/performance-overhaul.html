Performance overhaul

The final rewrite improves typing, preview and live edits. History-heavy reloads, large paragraphs and reconnect are still slower than main. Frozen production builds, local sync servers and disposable accounts were used throughout.

120 fps is not established. The final continuous 128 KiB trace had one 9.23 ms main-thread task, mostly garbage collection, versus 29.04 ms in main. The earlier rewrite's 162 ms persistence stall is gone. This headless browser presents near 60 Hz, so it cannot certify 120 Hz presentation.

What still needs work

  • A retained-history 128 KiB reload takes 1,079.7 ms versus main's 993.6 ms. The earlier cache held 286,548 character atoms for about 131,000 visible characters. Cooperative decoding spreads this work across tasks; it does not eliminate the work.
  • A 1 MiB paragraph reload takes 3,162.2 ms versus 2,723.0 ms. End typing reaches a paint opportunity in 31.5 ms versus 27.7 ms. Native input often approaches or exceeds the 8.3 ms budget. Main's beginning edit did not reach the required source-change state before the deadline; middle was skipped. That result is unverified automation, not an app-crash claim.
  • 128 KiB find takes 29.0 ms versus 25.5 ms. Offline reconnect to peer takes 80.4 ms versus 46.8 ms. Normal live edits are faster at 79.5 ms versus 304.0 ms.
  • Main switching missed the required-state deadline. Final rewrite multicursor timing lost the injected probe after a browser-daemon restart. Main replaced 1,298 selections in 84.2 ms, p95 90.0 ms. The previous report retains earlier rewrite multicursor evidence; this final cell is missing.

Measured causes and changes

  • Rich 32 KiB text mounted too much native text and overlay DOM. Bounded windows and batched geometry removed repeated write/read layout work. Search reuses match lists. Final beginning typing is 12.3 ms versus the earlier rewrite's 30.3 ms.
  • Preview waited for comment alignment. Rendering before alignment reduced 128 KiB preview from 476.8 ms to 34.1 ms; main takes 66.4 ms. The rendered 1,297 reference links were verified during the preceding patch comparison.
  • Checkpoint decoding and Replica.restore produced an 822 ms IndexedDB callback. Bounded cooperative hydration reduced the largest callback to 22.26 ms in the intermediate no-profiler trace, while total reload time remained around one second.
  • Snapshot capture synchronously materialized cold durable text. Cooperative capture and warming durable materialization removed the 162 ms and then 81 ms continuous-typing stalls. The final remaining largest task is mostly collection.
  • Immutable atom storage now uses Effect Chunk; SQLite statements reuse Bun's query cache. The module test below exercises the combined resulting sync path.

An apparent 197 ms animation callback in an early CPU trace was profiler startup: its first sample consumed 195.975 ms. It is excluded from application-cost claims. Final continuous traces use no CPU-profiler category.

Collaboration and fallback

The forced HTTP polling path was verified by rejecting WebSocket construction in disposable profiles and observing the live HTTP route. Polling edit-to-peer median was 75.9 ms, p95 85.7 ms; reconnect median 71.0 ms, p95 71.6 ms. These local figures do not predict internet polling latency.

A separate continuous sync behavior probe sent 25 edits every 40 ms. Its first peer update arrived after 46.5 ms and 23 updates arrived before typing ended. No focus or online events occurred. Local activity immediately drains and synchronizes; the session's separate 500 ms debounce does not block this path.

The public-boundary 24-writer test passed 1,267 assertions. It committed 192 operations across eight rounds using mixed live transports, persisted clients, reconnect and reader permissions. Commit-request median fell from 258.5 to 118.7 ms, p95 from 508.5 to 247.1 ms. Complete journey throughput rose from 24.9 to 52.1 operations/second. Clients, server, convergence barriers and assertions run together; pure server capacity and 20-writer browser frame rates remain unmeasured.

A clean fallback-parser probe measured actual message-handler slices. A 1.125 MiB prose source used 202 turns with maximum 0.6 ms, previously 10.8 ms. Large unmatched links, unclosed fences and many small fences stayed at or below 0.6 ms. This is a module scheduling result, not an E2E frame-rate result.
